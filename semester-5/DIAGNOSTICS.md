# Консоль, журнал, профайлер и Frame Debugger

Инструменты открываются кнопкой **Diagnostics** или **⌘⇧D**. Изначально в нижней области dock находятся
Console, Log, Profiler и Frame Debugger, справа — Renderer. Системы и проходы измеряются в общем движке; код лабораторной
может добавлять команды и регистрировать собственные GPU-ресурсы.

## Dock и отдельные окна

- Перетащите вкладку на другую вкладку, чтобы изменить порядок или объединить панели в одной области.
- Во время перетаскивания над viewport появляются цели **Dock left / right / bottom**.
  Они позволяют закрепить панель даже в пустой области. В каждой области может быть несколько вкладок;
  левая, правая и нижняя области показываются одновременно. Разделители между областями перетаскиваются.
- Перетащите вкладку за пределы окон приложения, дважды щёлкните по ней или нажмите значок
  **↗** рядом с вкладками, чтобы открыть отдельное обычное macOS-окно. Его можно перемещать
  на другой монитор, масштабировать и сворачивать независимо от сцены.
- В отдельном окне **Dock to…** выбирает область, **Return to workspace** возвращает панель вниз
  (Renderer — вправо). Закрытие отдельного окна также возвращает панель в workspace.
  Можно перетащить его вкладку обратно на вкладки или цели над viewport.
- Меню **…** и контекстное меню вкладки позволяют выбрать область или скрыть панель.
  **Panels** в верхней панели повторно открывает скрытый инструмент и предлагает **Restore default layout**.
- **Diagnostics / ⌘⇧D** скрывает или показывает диагностические области и окна; настройки Renderer остаются доступны.

Порядок вкладок, выбранные панели, скрытые инструменты, отдельные окна и их координаты сохраняются
в UserDefaults с ключом на основе `settingsName` приложения. Размеры областей сохраняет NSSplitView.
Сброс раскладки не меняет настройки рендера, журнал и сцену. Если сохранённая раскладка повреждена,
в журнал выводится предупреждение и восстанавливается стандартная. Окно с отключённого монитора
возвращается в видимую часть доступного экрана.

Содержимое каждого инструмента принадлежит одному постоянному `NSHostingView`; состояния инструментов
отдельно принадлежат `DiagnosticsViewState` и не зависят от жизненного цикла представления SwiftUI.
При переключении вкладок и переносе между окнами сохраняются ввод консоли, фильтры,
замороженные выборки и состояние инспектора.
В узкой области широкие инструменты имеют горизонтальную прокрутку. Все окна используют одну сессию,
один рендерер, общий журнал и историю профайлера. Закрепление панели не создаёт дополнительные GPU-циклы.

Код dock изолирован в EngineMac: `DockLayout` проверяет раскладку и переходы,
`DiagnosticsDock` управляет окнами и хранением, `DockWorkspaceController` — разделителями и drop-зонами,
`DockViews` — вкладками и переносом постоянных контейнеров. EngineCore и EngineMetal от dock не зависят.

## Console

Введите `help`. Enter или Run выполняют команду, ↑/↓ выбирают историю, Tab дополняет имя команды.
История ограничена 200 командами. Поддерживаются одинарные/двойные кавычки и экранирование пробелов.
Ошибки разбора, неизвестные команды и неверные настройки выводятся в журнал.

```text
help
passes
stats
entities
set fps 60
set msaa 4
set exposure 1.5
set fov 70
set speed 4
set wireframe on
set background 0.02 0.03 0.05
pause
step
capture
resume
profile on
profile off
profile clear
get
reset
echo "hello engine"
log warning MySystem "diagnostic message"
trace "/new/path/Frame.gputrace"
clear
```

`pause` останавливает обновление сцены и рисование, `step` выполняет один шаг с `dt = 1 / targetFPS`.
При активном Frame Debugger кнопка Step также обновляет захват. Resume сбрасывает часы, поэтому время
паузы не превращается в большой скачок анимации. Изменённые при паузе настройки применяются при
следующем рисовании; консольный `set` автоматически запрашивает один кадр.

Это консоль команд движка. Реестр расширяется через `session.commands.register`:

```swift
session.commands.register("scene.reload", help: "Reload the laboratory scene") { [weak scene] arguments in
    try scene?.reload()
    return "Scene reloaded."
}
```

Передавайте зависимости явно и используйте слабый захват, если владелец команды также владеет реестром.

## Журнал

`session.log.write(.info, category: "MySystem", "Message")` записывает структурированное событие:
ID, дату, уровень, категорию и сообщение. Уровни: debug, info, warning, error.

Один журнал принимает сообщения приложения, ресурсов, консоли и ошибки Metal. Вкладка Log позволяет
фильтровать уровень и текст, отключать автопрокрутку, замораживать отображение и копировать сообщения.
Clear очищает память; файл сохраняется. Export log выгружает содержимое кольцевого журнала в JSON.

В памяти хранятся последние 5000 событий. Файл `Logs/engine.jsonl` расположен рядом с пользовательским
`settings.json` в Application Support. Запись идёт через отдельную serial queue. При достижении 4 MiB
выполняется ротация в `.1`, `.2`, `.3`. При ошибке записи сообщение остаётся в памяти и появляется
событие категории LogFile. Также используется системный Unified Logging.

Запись сообщений непосредственно из Metal-шейдеров можно включить параметром
`enableShaderLogging: true` при создании EngineSession/MetalRenderer. В этой версии Metal вызов
`makeLogState` несовместим с нативным `.gputrace`: Metal требует перезапуска процесса без shader logging.
Поэтому **shader logging по умолчанию выключен**; журнал движка и сообщения об ошибках GPU работают всегда.
Встроенный захват ресурсов не зависит от этого ограничения.

## Profiler

Профайлер хранит последние 300 кадров и показывает:

- графики CPU/GPU в миллисекундах, среднее, p95 и максимум CPU;
- CPU-время каждой системы и кодирования каждого прохода;
- GPU-время проходов, измеренное через Metal 4 timestamp counter heaps;
- ожидание свободного GPU-слота, число draw calls и объектов;
- объём ресурсов residency set текущего слота кадра — это не суммарное потребление памяти процесса/GPU.

GPU-результаты читаются после сигнала завершения соответствующего слота. Пока GPU не закончил кадр,
результат помечен pending. График позволяет выбрать исторический кадр; таблица относится к его ID.
Без выбора используется последний кадр с готовыми GPU-результатами. Freeze profiler фиксирует историю;
Export сохраняет её в JSON вместе с деталями систем и проходов.

GPU timestamps отключаются переключателем или `profile off`. CPU-измерения остаются доступны.
Измерения на границах проходов включают соответствующие зависимости/барьеры; это не измерение отдельных
shader instructions. Timestamp-запросы сами имеют накладные расходы. Кадры со снимками ресурсов или
нативным захватом отмечаются `instrumented`; их время включает дополнительные операции диагностики.

Собственные draw/dispatch-команды учитывайте через `PassContext.recordDraw(count:)`.
Для разбора отдельных GPU-команд и аппаратных подробностей используйте Xcode GPU trace.

## Frame Debugger

**Capture frame** / **⌘⇧C** / `capture` сохраняет следующий кадр и останавливает приложение.
В списке слева находятся все зарегистрированные проходы в порядке исполнения. Для каждого сохранены
его входы/выходы и снимки текстур/буферов **после этого прохода**. Последующее рисование эти данные не меняет.

Встроенные ресурсы регистрируются автоматически:

- HDR, depth, MSAA attachment и финальная surface;
- GPUFrame uniforms, активный диапазон GPUObject, vertex buffers мешей.

В инспекторе текстуры доступны RGB/R/G/B/A, отдельные MSAA-сэмплы, увеличение, экспозиция превью,
Auto range и значения пикселя по X/Y. HDR визуализируется с tone mapping; экспорт сохраняет исходные
данные. Depth показывает device depth 0…1; Auto range помогает увидеть небольшие различия возле 1.

Инспектор буфера показывает размер/stride, описание структуры, hex-байты и интерпретацию Float32,
UInt32, Float16 или UInt8. Просмотр постраничный, чтобы большой буфер не перегружал интерфейс.
Адреса учитывают смещение захваченного диапазона относительно начала исходного буфера.
Можно экспортировать отдельный ресурс в binary или весь кадр в JSON с метаданными и base64-данными.
Discard capture освобождает сохранённый снимок.

### Собственные ресурсы прохода

В `prepareFrame` регистрируйте буферы/текстуры:

```swift
context.frame.useResource(buffer) // residency + retention; автоматическая регистрация для capture
context.frame.inspectBuffer(
    "Particles", buffer: buffer, range: 0..<activeBytes,
    stride: MemoryLayout<Particle>.stride,
    schema: "Particle: position float4 @0; velocity float4 @16"
)
context.frame.inspectTexture("Velocity", texture: velocityTexture)
```

`inspectBuffer` задаёт доступный для просмотра диапазон и структуру; `inspectTexture` задаёт имя.
Эти методы не заменяют объявление зависимостей прохода и регистрацию residency. Для ресурсов,
не переданных в `useResource`, регистрацию residency необходимо выполнить отдельно.

Захват выполняется GPU-copy/compute-командами с барьерами. Private buffers читаются через staging;
MSAA color/depth сохраняются посэмплово в RGBA32Float. ForwardPass при захвате сохраняет multisample
attachment вместе с resolve. CPU читает staging только после завершения GPU. Временные копии
освобождаются после формирования независимых Data-снимков.

Бюджет readback — 256 MiB на кадр. Если он исчерпан, оставшиеся ресурсы получают явную пометку;
метаданные не теряются. Встроенное превью поддерживает 2D color/depth с распространёнными форматами:
RGBA16/32Float, BGRA/RGBA8, R32/16Float, R8 и Depth32Float. Неподдерживаемые форматы, массивы/3D
и memoryless attachments помечаются с причиной. Для полного просмотра таких ресурсов используйте
нативный захват. Превью уменьшается до 512 px по ширине; pixel inspector читает полный захваченный размер.

## Xcode GPU trace

Кнопка **Xcode GPU trace…** выбирает файл, записывает один кадр в `.gputrace` и сохраняет документ
для GPU Debugger Xcode. Команда `trace` принимает новый путь. Существующие документы не перезаписываются.
Info.plist приложения содержит MetalCaptureEnabled; shared scheme также задаёт MTL_CAPTURE_ENABLED=1
для запуска и тестов. В других приложениях на этом движке включите эту возможность аналогично.

Откройте полученный файл в Xcode для просмотра отдельных draw calls, pipeline states, привязок ресурсов,
шейдеров и ресурсов, которые не поддерживает встроенное превью. Перед capture ожидается завершение
предыдущих кадров; captured command buffer создаётся внутри области нативного захвата.

Нативный Metal capture требует запуска без `enableShaderLogging`; в противном случае команда возвращает
понятное сообщение о необходимости нового процесса. Публичный API не отключает эту возможность молча.

## Проверки

Основной запуск тестов — shared scheme Sandbox:

```sh
xcodebuild -workspace semester-5/GraphicsEngine.xcworkspace -scheme Sandbox \
  -destination 'platform=macOS,arch=arm64' -derivedDataPath /tmp/graphics-engine-build test
```

Дополнительные тесты проверяют разбор/историю команд, ограничение/фильтрацию/ротацию журнала,
запоздалые GPU-результаты, снимки обоих проходов, содержимое depth/MSAA и буферов, неизменность снимка,
GPU timestamps и создание непустого нативного `.gputrace`. Без Metal 4 GPU-тесты явно пропускаются;
нативный тест также требует включённого GPU capture.

Основа API: [Metal 4 timestamps](https://developer.apple.com/documentation/metal/mtl4commandbuffer/writetimestamp(counterheap:index:)),
[программный GPU capture](https://developer.apple.com/documentation/xcode/capturing-a-metal-workload-programmatically).
